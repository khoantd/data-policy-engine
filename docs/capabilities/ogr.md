# OpenGuardrails

**System ID:** `ogr`  
**Title:** OpenGuardrails  
**Kind:** System  
**Description:** Optional runtime for GuardEvent evaluation  
**Tags:** external  

---

## Purpose
OpenGuardrails provides a runtime environment that evaluates *GuardEvents* generated by ROS Policy. It enables policy enforcement for agent or LLM workflows that require on‑the‑fly decision making about retention, classification, or other data handling actions. When installed, it extends ROS Policy’s Guardrails evaluation capability, allowing external components to query GuardEvent outcomes in real time.

---

## Responsibilities
| Area | Responsibility |
|------|----------------|
| GuardEvent Evaluation | Accept GuardEvents from ROS Policy and return evaluation results (retain, archive, anonymize, delete, etc.). |
| Policy Integration | Load and interpret Guardrail policies defined in ROS Policy’s `GuardrailPolicyStore`. |
| Runtime Management | Provide a stable, low‑latency service that can be queried by external agents, micro‑services, or LLM workflows. |
| Compatibility | Ensure evaluations conform to the same semantics as ROS Policy’s internal Guardrails engine. |
| Observability | Log evaluation traces and expose metrics to aid debugging and performance monitoring. |

---

## Interfaces and Dependencies
- **Outgoing Relationships**
  - **ROS Policy – Guardrails**: Calls the Guardrails evaluation endpoint (or equivalent port) when the OpenGuardrails runtime is installed.
- **Input Interfaces**
  - *GuardEvent API*: REST/GRPC endpoint for receiving GuardEvents.
  - *Policy Store API*: Reads Guardrail policies from ROS Policy’s `GuardrailPolicyStore`.
- **Output Interfaces**
  - *Evaluation Result API*: Returns the decision back to the caller (e.g., agent or workflow orchestrator).
  - *Telemetry/Logging*: Exposes logs and metrics via standard observability stack (e.g., OpenTelemetry, Prometheus).
- **Dependencies**
  - ROS Policy core components (policy store, evaluator).
  - Shared data format for GuardEvents (YAML/JSON schema defined in ROS Policy).
  - Networking (HTTPS/TLS) for secure communication with ROS Policy and consumers.

---

## Constraints and Notes
- **Optional**: OpenGuardrails is not required for ROS Policy to function. It is only activated when external workflows need GuardEvent evaluation.
- **External System**: As an external system, it must expose well‑documented APIs but no guarantees are made about internal implementation details.
- **Deployment**: Typically deployed as a separate container or service; integration with ROS Policy is performed via configuration (e.g., service discovery or API endpoint reference).
- **Versioning**: Must maintain backward compatibility with the GuardEvent schema used by ROS Policy to avoid breaking existing integrations.
- **Security**: All communications should be authenticated and encrypted; policy data should be protected at rest.
- **Performance**: Expected to provide sub‑millisecond to low‑millisecond latency for GuardEvent evaluations to support real‑time workflows.
